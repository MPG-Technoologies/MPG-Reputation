## Smallest safe implementation

1. **`src/app/layout.tsx`:** use the verified working product identity in `applicationName`, title and accurate prelaunch description. Set root fallback `robots: { index: false, follow: false, nocache: true }`. This covers pages without route-level metadata. Existing route-level rules remain unchanged.
2. **`src/app/robots.ts`:** generate an explicit `User-agent: * / Allow: /` policy **without** `Sitemap:`. This permits crawlers to *read* the prelaunch HTML `noindex` directives; it **does not grant indexing permission**. Search engines may still crawl URLs; the `noindex` metadata is what directs compliant engines not to index. Robots directives are not authentication or confidentiality controls.
3. **`src/proxy.ts`:** exclude only `robots.txt` from the Supabase auth-refresh matcher. Preserve existing `/app`, `/onboarding` and `/login` authentication behavior.
4. **`test/integration/mr10j-prelaunch-seo-contract.test.ts`:** seven focused assertions for identity, global noindex, marketing routes, robots directive, proxy exclusions, absent canonical/sitemap and development-only campaign preview.

### Why NOT `Disallow: /`?

Google Search Central explicitly documents that a crawler blocked by `robots.txt` cannot see a page's `noindex` tag; this can lead to a linked URL appearing in search despite its content remaining unavailable. The correct prelaunch choice for **discoverable but intentionally non-indexable** staging pages is to allow crawling and emit `noindex` metadata. **This does not make the site publicly marketed or approved for launch.**

References:
- https://developers.google.com/search/docs/crawling-indexing/block-indexing
- https://nextjs.org/docs/app/api-reference/file-conventions/metadata/robots
- https://nextjs.org/docs/app/api-reference/file-conventions/metadata
